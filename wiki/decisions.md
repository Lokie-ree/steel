# Decisions

Append-only architecture decision log for the ecosystem. Gap this file covers that no existing doc does: cross-repo rulings had no durable home — they lived in conversation memory and spoke-local docs, invisible at the hub. One entry per ruling; never edit past entries, append corrections as new entries.

**Cite rulings by ID, not by date.** Eight of the entries below share a date with another ruling, so `[[decisions]] 2026-08-03` names three different rulings and therefore resolves to none of them. The ID carries the date, so it stays readable in prose and still matches an older citation on a plain text search. A letter suffix appears only when a date carries more than one ruling, in the order they appear in the table.

**`Status` is the one field that may change on a past row.** Append-only protects the ruling; nothing protected the pointers *to* it, so a ruling amended later read identically to one still standing alone. `Status` is metadata about the row, not part of the ruling — the `Ruling` and `Why` cells are never edited. Values: `active` · `amended by <ID>` (extended, still in force) · `superseded by <ID>` (reversed). `Where it binds` is likewise a pointer column, maintained as its targets move.
