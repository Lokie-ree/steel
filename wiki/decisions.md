# Decisions

Append-only architecture decision log for the ecosystem. Gap this file covers that no existing doc does: cross-repo rulings had no durable home — they lived in conversation memory and spoke-local docs, invisible at the hub. One entry per ruling; never edit past entries, append corrections as new entries.

| 2026-08-03 | **Systems key on the calendar date, never the A/B label.** Any module state, collection protocol, notebook field, or CSV column that stores "A Day" / "B Day" is wrong. Store the date; derive the label per cohort at read time. | P-Tech A Day is T/Th/F. Instrumentation A Day is M/W. **The same calendar day carries the opposite label depending on which cohort you ask** — so a field named `day_type` silently merges two cohorts' opposite days and no error is ever raised. The label is a transcription of the date; the date is the derivation. Same class of rule as *git state is derived, never transcribed* (`CLAUDE.md`), and it corrupts quietly rather than loudly, which is why it is written before the first CSV rather than after. | [[collection-protocol]] · [[depth-criteria]] · `course-lab` telemetry schema · [[../initiatives/edgeex-build-family]] |
| 2026-08-03 | **The fall build surface is Algebra II. The rest of the math spectrum is a support obligation, not a build obligation.** One course, one prep, one 50-minute container. Stray Algebra III students inside the block are a differentiation problem, not a second build. | Being the only math teacher in the building creates real coverage duties — RTI 7:00–8:00, the ECO duty block — and the inference *"I support the whole spectrum, therefore I build for the whole spectrum"* is the exact move that turned six preps into six builds before the 2026-07-22 shrink corrected it. Support is a schedule fact; build surface is a capacity decision, and they are not the same quantity. Entering the session the surface was "the entire math spectrum"; leaving it is one course. | [[../sprint/2026-fall-runway]] · [[edge-ex-courses]] · [[../initiatives/edgeex-build-family]] |

The manipulative already exists as the sandbox state at the end of a shipped module; it does not need to be rebuilt as a product. Written this week specifically as cheap insurance while the build instinct is loud: **twelve widgets is a year, one door is a routing PR.** Guard: this must not become precedent for reducing arc friction — a second entry point is a different use case, not a smoothing of the full arc, whose difficulty stands. | [[../projects/creative-lab]] · [[../projects/course-lab]] · [[patterns]] · [[../sprint/2026-fall-runway]] §Not doing |

| 2026-07-24 | **course-lab stays client-side — NOT-DOING a backend.** Persistence remains `localStorage` with the in-memory fallback ([[patterns]] §6). This is not a maturity gap versus project-studio-coach's Convex: that stack was *required* there — RAG needs a server, and plan-gating is enforced at the query projection, which only exists server-side. course-lab has no server-side logic to protect. Staying client-side buys three things a backend would spend: no district data agreement, no auth surface, no PII leaving the Chromebook. **Two named triggers reopen this:** (a) collection fails in a real class period, or (b) a second teacher adopts course-lab. Absent either, a backend is scope, not progress. | The two repos get compared on stack sophistication and the comparison is wrong — studio-coach's server is load-bearing for its own reasons, and copying it into course-lab would import compliance cost to solve a problem course-lab does not have. Naming the triggers means the decision can be revisited on evidence instead of on unease. | [[../projects/course-lab]] · [[patterns]] §6 · [[depth-criteria]] |
